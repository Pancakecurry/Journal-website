# User Journeys

## 1. The ordinary day

1. The user opens the app and arrives at Today after any necessary unlock.
2. Today reflects the current date and what already lives there.
3. A morning check-in may be offered, but can be skipped without consequence.
4. The user adds moments throughout the day; each addition visibly joins the timeline.
5. An evening wrap-up may be offered and answered partially, fully, or not at all.
6. The Day becomes part of history regardless of how much was recorded.
7. Later, the user revisits it through Calendar, Journal, Search, or a memory surface.

Success means the Day feels inhabited by the user's life, not completed like a task.

## 2. Capture one sentence

1. From Today or the near-global action, the user opens Quick Capture.
2. The interface asks “What happened?”
3. The user enters “Had ramen after class.”
4. The user saves immediately without choosing a category.
5. The sentence appears in chronological context on Today.

The path must remain fast on mobile and desktop, work by keyboard, preserve input through recoverable failures, and eventually honor offline behavior.

## 3. Add a photograph or richer moment

1. The user opens Quick Capture and optionally chooses Photo or attaches media.
2. The user may add a caption, mood, or other context, but none is required.
3. The photograph appears as a moment within the Day.
4. Privacy and storage/sync state are understandable where relevant.

Media remains private by default. Exact storage architecture is deferred.

## 4. Write a long journal entry

1. The user begins from Today or Journal.
2. The interface quiets from Desk/Notebook into Paper.
3. Writing receives readable typography, generous margins, minimal controls, and clear autosave confidence.
4. The user can leave and later recover or continue the entry.
5. The finished entry is readable from both its Day and the Journal library.

## 5. Morning or evening reflection

1. The user chooses an optional reflection prompt.
2. One conversational question is shown at a time.
3. The user answers, skips, stops early, or continues.
4. Existing responses are safely retained.
5. A completed evening reflection may receive a quiet stamp-like acknowledgement.

The interface never uses guilt, streak loss, or an incomplete state when prompts are skipped.

## 6. Revisit a day

1. The user opens Calendar, sees subtle indicators that something lives on certain dates, and selects one.
2. A preview or historical Day opens in a read-first state.
3. Moments, media, writing, and reflections retain their original Day context.
4. The user may edit existing content or add a backfilled memory.
5. Later-added or edited provenance is available where technically appropriate without displacing the event date.

## 7. Find past writing

1. The user opens Journal or global Search.
2. Chronology, a query, filter, or bookmark helps locate writing.
3. The result opens in a focused reading view.
4. The user can return to the Day in which it belongs.

Search is retrieval, not a new content hierarchy.

## 8. Use the app while offline

1. The user opens a locally available Day without connectivity.
2. Offline status is clear but not alarming.
3. The user writes, records moments, edits available entries, uses check-ins, browses available days, and attaches locally available photos where feasible.
4. The interface communicates what is safely stored locally and what, if anything, awaits synchronization.
5. Reconnection resolves through a future, explicitly designed sync/conflict strategy.

Task 000 defines the desired experience but does not choose its technical implementation.

## 9. Shape My World over time

1. A new user begins with a clean, prepared environment and a restrained chosen accent.
2. Authored days, photographs, bookmarks, keepsakes, and organizational choices create traces of use.
3. The environment becomes recognizably personal over months.
4. Optional future games remain tucked inside My World and may create attachable journal artifacts.

Accumulation never depends on XP, currency, streaks, or engagement pressure.
