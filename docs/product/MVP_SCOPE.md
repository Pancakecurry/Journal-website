# MVP Scope

## Product hypothesis

The first meaningful release must prove:

> Can recording one ordinary day feel unusually enjoyable?

The MVP is a coherent Day-centered journaling loop, not a breadth demo. Scope choices must protect fast capture, trustworthy persistence, calm writing, private ownership, and useful history.

## In scope

### Onboarding

- Minimal introduction to the product and its private, Day-centered model
- Lightweight preferences
- Initial visual accent choice
- Optional reflection preference

### Today

- Current date and warm contextual greeting
- Optional mood
- Chronological timeline that visibly accumulates
- Fast, uncategorized text capture
- Images and journal entries associated with the Day
- Optional morning check-in and evening wrap-up
- A restrained completed-reflection acknowledgement, never a completion score

### Journal

- Focused long-form editor
- Autosave with understandable status and recovery behavior
- Archived reading associated with original days

### History

- Calendar and historical-day views
- Basic search
- Backfilled memories attached to when they happened, with later-added or edited metadata where appropriate

### Foundation

- Private user data and explicit privacy boundaries
- Offline/local-friendly core behavior
- Responsive desktop and mobile experience
- Accessibility and reduced motion
- Robust persistence, failure handling, and recovery

## Explicitly deferred

- Rich tracker builder and advanced tracker visualization
- Extensive desk customization, pets, or garden
- Keepsake and mini-game suites
- Semantic AI, journal assistant, and advanced analytics
- Social features, public profiles, and follower systems

Deferred work is sequenced in the [roadmap](../ROADMAP.md). No implementation technology is selected by this scope document; see the [decision log](../architecture/DECISION_LOG.md).

## MVP acceptance lens

A viable slice must support the full ordinary-day loop, including sparse days and interrupted/offline use where applicable. A screen mock or shallow happy path is not sufficient. Future implementation tasks should apply the definition-of-done principles in the [roadmap](../ROADMAP.md).
